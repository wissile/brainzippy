## Review findings (milestone 1)
Two independent agents reviewed the code they did not write. All findings below were triaged; fixes were re-verified by the full test suite (36 unit, 41 Playwright passing) and screenshots.

| Sev | Finding (reviewer) | Resolution |
|---|---|---|
| Critical | Tutorial/idle **hand pointer never visible**; becomes a grid row and squashes the board (CSS specificity) (QA) | Fixed: zero-specificity `:where()` selector; e2e "hand appears inside viewport and does not shift layout" on all 4 devices |
| High | Server backup write-only; grown-ups text promised it survives reset (Security H1) | Sync disabled (D-011); text corrected |
| High | Corrupt/old resume snapshot could blank the game permanently (Security H2) | `parseRoundSnapshot` + version field + ErrorBoundary; unit + e2e tests |
| High | Idle help pointed at a (wrong) number choice (QA) | Now replays "How many?" and points at the objects |
| High | Age tiles exposed as `listitem`, not buttons (QA, WCAG 4.1.2) | Roles removed; e2e asserts role=button |
| High | Speech bubble covered objects on phones (QA) | D-012; e2e "captions never cover objects" on all devices |
| Medium | Body size cap bypassable without Content-Length (Security M2) | Streaming byte-counted reader; unit test with chunked body |
| Medium | Parent delete failed silently; no parent gate (Security M3) | Checks `res.ok`, keeps id + retry message; arithmetic parent gate; e2e |

## Security & child-privacy review fixes (2026-11-18)
| ID | Decision | Why / evidence |
|---|---|---|
| S-1 | `wrangler.jsonc` top level is `APP_ENV="production"`; development only from gitignored `.dev.vars`; `isDev()` also requires a `localhost`/`127.0.0.1` request URL; cron code passes no URL and never gets dev behaviour | A deploy that falls back to the top level (unset `CLOUDFLARE_ENV`) must not enable dev links, the dev signing secret, fake Stripe or rate-limit bypasses. Unknown `CLOUDFLARE_ENV` is a hard error in wrangler 4.163.0 (verified locally; docs silent): https://developers.cloudflare.com/workers/vite-plugin/reference/cloudflare-environments/ · https://developers.cloudflare.com/workers/wrangler/system-environment-variables/ |
| S-2 | `FRIENDS_ENABLED` flag ("false" top level + production, "true" staging + `.dev.vars`): flagged routes are skipped by the router (404, indistinguishable from a missing route); `/api/me` returns `features.friends` so the dashboard hides friends/leaderboard/challenges | Legal blocker: verifiable parental consent for social features is a lawyer's decision (docs/legal/COPPA_CHECKLIST.md §4) |
| S-3 | Other families see only a **public name** = adjective + creature from curated 40 × 40 lists (`src/account/publicName.ts`), default derived from the child id (FNV-1a + murmur3 finaliser), changeable by the parent; the child-typed monster name is no longer accepted by the API and migration `0006` drops `children.monster_name` | A free-text name typed by a child can be a real name; generated names remove that disclosure. Unit tests check every combination against a blocked-word list (across the boundary) and rude initials |
| S-4 | Legacy `/api/parent-signup/verify`: GET page → POST confirm (like `/api/auth/verify`); `/api/parent-signup` always answers `pending`. Both confirmation pages show the email address being confirmed / signed in | Mail scanners prefetch GET links (consent must not be recorded by a robot); a `verified` reply revealed which emails have accounts; showing the email makes a planted sign-in link (login CSRF) visible |
| S-5 | Account deletion = cancel subscription → delete Stripe Customer → delete rows; the client also disables this device's reminders | Deleted accounts must leave no saved payment method; push subscriptions are device-scoped (no account link), so the server can't find other devices' subscriptions — documented, 180-day purge covers them |
| S-6 | Push cron selects `ORDER BY last_sent IS NOT NULL, last_sent, updated_at, id`; per-IP limits key IPv6 on the /64 | A run capped at 40 sends (and 5000 rows) must not starve the same devices by insertion order; one IPv6 subscriber can rotate through a /64 |
| S-7 | Guest API: **disable** writes (404) unless `GUEST_SYNC_ENABLED="true"`, keep GET/DELETE; per-IP limits apply if re-enabled | Client sync is off (D-011), so open unauthenticated writes only let anyone fill D1; disabling beats rate-limiting for data minimisation |
| S-8 | Static + API: HSTS `max-age=63072000; includeSubDomains` (no preload), COOP `same-origin`, CSP `worker-src 'self'`; Stripe event-id purge moved to the daily job; custom free-access codes removed | Review items 10, 12, 13. Preload is irreversible in practice, so left to the owner |
| S-9 | Webhooks re-fetch the subscription from Stripe for `customer.subscription.*` and derive state from it (fake Stripe keeps its own subscriptions to answer) | `event.created` has 1-s resolution and Stripe doesn't guarantee order; a late `created` payload (trialing) for an old subscription could replace a live one. (Stripe's webhook guide, https://docs.stripe.com/webhooks, covers event ordering; that page could not be re-checked in this session.) |
